# Reflection 4: Logic Programming & Formal Semantics

## 🎯 Purpose

This reflection is an opportunity to demonstrate your understanding of logic programming and formal semantics.

Unlike assignments, this is not about writing code. Instead, this is your chance to:
- explain ideas in your own words
- make connections across topics
- reflect on how your understanding has evolved

---

## What to Include

Your reflection should demonstrate your understanding of the following concepts:

---

### Logic Programming

Explain:
- what logic programming is
- how it differs from other paradigms (e.g., imperative, functional, object)

Include:
- how computation works in a logic programming language
- the role of rules, facts, and queries

---

### Prolog

Explain:
- how Prolog programs are structured
- how Prolog solves problems (e.g., unification, backtracking)

Include:
- what it means for a query to succeed or fail

---

### Lists & Pattern Matching

Explain:
- how lists are represented in Prolog
- how pattern matching works (e.g., `[H|T]`)

Include:
- how recursion is used to process lists

---

### Prolog I/O & Interaction Loops

Explain:
- how Prolog can interact with users (e.g., `read`, `write`)
- how recursion can be used to simulate loops

Include:
- how this differs from traditional looping constructs in other languages

---

### Formal Semantics

Explain:
- what formal semantics is
- why it is important for programming languages

Include:
- how Prolog can be used to define semantics (e.g., interpreters using rules)
- your understanding of **abstract syntax trees (ASTs)** and evaluation (e.g., `val1`)

---

### Reflection

Discuss:
- which concept in this unit was the most difficult to understand
- which concept “clicked” the most for you
- how your understanding of programming languages has changed
