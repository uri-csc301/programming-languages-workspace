# Reflection 2: Functional Programming

## Purpose

This reflection is an opportunity to demonstrate your understanding of the concepts covered in our Standard ML unit.

Unlike assignments, this is not about writing code. Instead, this is your chance to:
- explain ideas in your own words
- make connections across topics
- reflect on how your understanding of functional programming has developed

---

## What to Include

Your reflection should demonstrate your understanding of the following concepts:

### Types

Explain the role of types in programming languages.

Include:
- What it means to think of a type as a set of values
- The difference between primitive and constructed types
- How types help prevent errors
- How working with types in SML compared to languages you used before

---

### Pattern Matching

Explain how pattern matching works in SML.

Include:
- How pattern matching differs from using traditional `if` statements
- How pattern matching helps with lists, tuples, and recursive functions
- An example of a problem where pattern matching made the solution clearer

---

### Polymorphism

Explain what polymorphism means in programming languages.

Include:
- The main idea of polymorphism
- At least one type of polymorphism we covered
- How SML uses parametric polymorphism
- Why polymorphism is useful when writing reusable code

---

### Higher-Order Programming

Explain what higher-order programming means.

Include:
- What it means for functions to be treated as values
- How functions like `map`, `foldr`, or `foldl` help solve problems
- What currying means
- How higher-order programming changes the way you think about solving problems

---

### Reflection

Discuss:
- Which concept from this unit was most difficult for you to understand
- Which concept “clicked” the most for you
- How working with SML changed your understanding of programming languages
- Whether functional programming felt natural, challenging, useful, confusing, or surprising to you
