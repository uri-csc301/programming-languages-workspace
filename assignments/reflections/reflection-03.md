# Reflection 3: Memory & Object-Oriented Programming

## Purpose

This reflection is an opportunity to demonstrate your understanding of how programs execute in memory and how Java implements these concepts.

Unlike assignments, this is not about writing code. Instead, this is your chance to:
- explain ideas in your own words  
- connect concepts across topics  
- reflect on how your understanding of program execution has developed  

---

## What to Include

Your reflection should demonstrate your understanding of the following concepts:

---

### Memory Locations for Variables

Explain how variables are stored in memory.

Include:
- what it means for a variable to be bound to a memory location  
- different types of variables (e.g., local variables, parameters, object variables)  
- how variables relate to the runtime stack and/or memory  

---

### Memory Management

Explain how memory is organized and managed in a program.

Include:
- the difference between **stack** and **heap** memory  
- what happens when a function/method is called  
- how memory is allocated and deallocated  
- how Java handles memory (e.g., garbage collection)  

---

### Parameters

Explain how parameter passing works in programming languages.

Include:
- different parameter passing methods (e.g., pass-by-value, pass-by-reference, pass-by-value-result)  
- how Java actually passes parameters  
- why objects in Java can appear to behave differently from primitive types  

---

### Object-Oriented Programming

Explain how object-oriented programming relates to memory and program execution.

Include:
- what objects are and how they are stored in memory  
- how methods interact with objects  
- the role of classes, fields, and methods  
- how working with objects differs from working with primitive values  

---

Discuss:
- which concept from this unit was the most difficult to understand  
- which concept “clicked” the most for you  
- how your understanding of how programs execute has changed  
- how this unit changed the way you think about programming
